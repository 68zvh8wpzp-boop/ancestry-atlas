# FamilySearch Cloud Browser Handoff Protocol

Use this protocol for every person-page audit that requires FamilySearch interaction.

## Successful route

1. Open or reuse the actual FamilySearch Cloud Browser tab.
2. Use the product’s **Open / Take over Cloud Browser** handoff control so the user can see and operate that tab.
3. Leave the target person/page or the visible FamilySearch human-verification challenge open in that handed-off tab.
4. Tell the user exactly what is visible and ask them to clear only the displayed hCaptcha/security challenge or sign-in step.
5. Wait for the user to say **Done**.
6. Reuse the same handed-off session and verify that the target page is now accessible.
7. Continue the one-person audit from that point; do not restart completed work or create a substitute internal-only tab.
8. If the handoff control is unavailable, say so plainly. Do not call an internal tab, screenshot, or CUA state “surfaced.”

## Current project constraints

- One person at a time; stop after each person.
- Preserve portraits, photos, documents, provenance, and exact transcriptions.
- Do not recapture autobiography-PDF images unless a FamilySearch version is materially higher quality or substantially distinct.
- Keep museum biographies third-person and free of workflow/source-audit language or research doubt.
- Never request or handle the user’s credentials in chat.

## Evidence for this protocol

The last five successful “Done” cycles used the surfaced FamilySearch Cloud Browser handoff, then resumed the existing or freshly opened tab after the user cleared hCaptcha. The current Marion failure occurred because an internal browser tab was mistaken for a user-visible handoff.
