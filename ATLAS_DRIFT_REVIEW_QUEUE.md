## Working rule for further audits

1. Refresh current `main` and the current Ancestry Atlas research handoff. Preserve the no-repeat register and the user's no-spending rule.
2. For an actual new person or relationship, update **`atlas-canonical-family-data.js` and `data/atlas-approved-graph-baseline.json`** together with its evidence rationale; don't insert people or parent links into presentation code.
3. For an original image, transcription or biography, add the identified source to the correct person ID. Preserve the high-resolution master and separate that from any crop, thumbnail or index-only link.
4. Evidence and story modules may enrich source cards and narrative presentation, but must not overwrite the canonical ID, name, years, places, branch, confidence or parentage.
5. Run `node atlas-graph-integrity-gate.mjs`, `node atlas-integrity-gate.mjs` and the new runtime record tests as well as all person-audit source tests. A published site is not evidence of a historical proof.
6. Review GitHub changes from concurrent research/audit work before merging. Require the release checks to pass and manually inspect a relevant iPhone person page, Tree, Globe, source gallery and Home/back/forward navigation after UI changes.

**Limitations:** The runtime index is a governed projection over current archival person data plus approved legacy overlays, not yet a fully normalized standalone source database. The gate checks structural consistency and preserved image bytes; it cannot substitute for reading a handwritten original.
